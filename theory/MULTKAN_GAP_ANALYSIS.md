# Анализ статьи KAN 2.0 / MultKAN и сравнение с LOKAN

*Liu Z. et al. KAN 2.0: Kolmogorov-Arnold Networks Meet Science, arXiv:2408.10205, 2024.*

---

## 1. Что нового в KAN 2.0 относительно KAN 1.0

KAN 2.0 — это не просто расширение архитектуры. Статья формулирует двунаправленный фреймворк:

```
Наука → KAN : встраивание знаний в сеть
KAN → Наука : извлечение знаний из сети
```

Три уровня научного объяснения, которые покрывает фреймворк:

| Уровень | Пример | Метод в MultKAN |
|---|---|---|
| Важные признаки | "y зависит только от x₁ и x₂" | attribution score + prune_input |
| Модульные структуры | "x₁ и x₂ перемножаются, а не складываются" | module(), tree(), auto_swap() |
| Символьные формулы | "y = sin(x₁)·exp(x₂)" | kanpiler, suggest_symbolic, auto_symbolic |

## 2. Архитектурные элементы KAN 2.0 / MultKAN

### 2.1 MultKAN: явные узлы умножения

**Ключевая идея**: умножение добавляется как отдельный тип узлов. Пользователь задаёт количество суммирующих (n^a_l) и умножающих (n^m_l) узлов при инициализации.

```python
model = MultKAN(width=[n0, n1, n2], ...)
# width = список пар [n^a_l, n^m_l] или просто int (тогда все узлы — суммирующие)
```

**Слой умножения** (нет обучаемых параметров!):
```
M_l(z_l) = concatenate(z_l[:n^a_{l+1}],  z_l[n^a_{l+1}::2] ⊙ z_l[n^a_{l+1}+1::2])
```

Пример на f(x,y) = xy:
- KAN: учится через `xy = ((x+y)² - (x-y)²)/4` — два суммирующих узла, неочевидно
- MultKAN: один умножающий узел, сразу интерпретируемо

**Критическое ограничение MultKAN**: тип узла (сумма vs произведение) задаётся **вручную пользователем**. Сеть не обучает выбор операции — только параметры сплайнов.

### 2.2 kanpiler — компилятор символьных формул

Конвертирует sympy-выражение в KAN-граф:

```python
model = kanpiler(input_variables, output_expression)
```

Процесс: формула → дерево выражений → KAN-граф (с dummy-рёбрами для выравнивания глубины). Протестирован на всех 120 уравнениях Feynman.

После компиляции можно:
- дообучить модель на данных (`perturb()` + обучение)
- расширить сеть (`expand_width()`, `expand_depth()`)

### 2.3 Attribution score (улучшенный)

Старый (KAN 1.0): `B_{l,i,j} = E_{l,i,j}` — просто стандартное отклонение активаций на ребре. Проблема: не учитывает, активно ли последующее ребро.

Новый (KAN 2.0): обратное распространение оценок от выхода к входу:
```
B_{l-1,i,j} = A_{l,j} · E_{l,j} / N_{l+1,j}
A_{l-1,i}   = Σ_j B_{l-1,i,j}
```
где `E_{l,j}` — std активаций на ребре, `N_{l+1,j}` — std активаций в узле.

### 2.4 Модульные структуры

**Anatomical modularity** (`auto_swap`): переставляет нейроны для минимизации суммарной длины связей. Делает кластеры визуально очевидными.

**Functional modularity** — три типа:

| Тип | Условие | Метод |
|---|---|---|
| Separability (add/mult) | f = g(x₁..xₖ) + h(xₖ₊₁..xₙ) | `test_separability` (Hessian ∂²f/∂xᵢ∂xⱼ = 0) |
| Generalized separability | f = F(g(...) + h(...)) | `test_general_separability` |
| Generalized symmetry | f = g(h(x₁..xₖ), xₖ₊₁..xₙ) | `test_symmetry` (∇_z(∇̂_y f) = 0) |

**Tree converter** (`model.tree()`): рекурсивно применяет тесты симметрии, строит дерево модульных зависимостей для произвольной функции или нейросети.

### 2.5 Три трюка для символьной регрессии

**Trick A**: обнаружить модульную структуру → переинициализировать с этой структурой → дообучить.

**Trick B**: `sparse_init=True` — разреженная инициализация. Символьные формулы соответствуют разреженным KAN.

**Trick C**: система контрольных точек (checkpoint):
```python
model.saveckpt()        # автоматически при каждом изменении
model.rewind('0.1')    # откат к версии 0.1 ("параллельная вселенная")
```
Позволяет тестировать альтернативные гипотезы (удалить ребро a или ребро b?).

### 2.6 Расширение сети

```python
model.expand_depth()          # добавить слой (identity-трансформации)
model.expand_width(layer, n)  # добавить нейроны (нулевые активации)
model.perturb()               # добавить шум к нулевым функциям для градиента
```

### 2.7 Приложения к реальной физике

| Задача | Метод | Результат |
|---|---|---|
| Законы сохранения (2D гармонический осциллятор) | KAN минимизирует `f(z)·∇H(z) = 0` | H₁ = x² + pₓ², H₂ = y² + pᵧ², H₃ = xpᵧ − ypₓ |
| Лагранжева механика (маятник, релятивистская масса) | kanpiler + finetune + suggest_symbolic | L = ½q̇² − (1 − cos q) |
| Скрытая симметрия (чёрная дыра Шварцшильда) | KAN как сплайн → машинная точность 10⁻¹⁵ | преобразование Гульстранда–Панлеве |
| Конституционные законы (Neo-Hookean материал) | kanpiler (линейный закон) + finetune | P₁₁ = 0.42(F₁₁² + F₁₂² + F₁₃² − 1) + 0.28 log|F| |

## 4. Что отсутствует в LOKAN относительно MultKAN

### 4.1 Критические отсутствия (P0)

**1. Встроенный тренировочный цикл `fit()`**

MultKAN имеет `model.fit(dataset, opt, steps, ...)` — стандартизированный цикл обучения с LBFGS/Adam, schedule обновления сетки, логированием.

LOKAN требует написания внешнего цикла вручную (как в `lokan_prod_group.ipynb`). Для статьи и воспроизводимости нужен стандартный API.

```python
# MultKAN
model.fit(dataset, opt='Adam', steps=500, lr=0.01, batch=64)

# LOKAN — пока только вручную
for epoch in range(EPOCHS):
    for batch in dataloader:
        ...
```

**2. `kanpiler` — компилятор формул в LOKAN**

MultKAN: `model = kanpiler(vars, expression)` преобразует sympy → KAN-граф.

LOKAN: такой инструмент отсутствует. Это важно для:
- тестирования гипотез (компилировать гипотезу, дообучить)
- встраивания априорных знаний
- воспроизведения Table/Fig стиля из MultKAN статьи

Трудность для LOKAN: нужно дополнительно кодировать информацию о том, какие операции (sum vs product) использовать в скомпилированном графе.

**3. `tree()` — конвертер в дерево модульных структур**

MultKAN: `model.tree()` рекурсивно применяет тесты сепарабельности/симметрии → строит дерево зависимостей.

LOKAN: частичный аналог есть через `symbolic_formula()` (строит sympy-выражение), но структурного дерева нет. Важно, потому что операционная структура LOKAN (logit routing) уже явно кодирует часть этой информации — осталось визуализировать.

**4. Демонстрации на реальных физических задачах**

MultKAN демонстрирует применение к 4 классам физических задач (законы сохранения, лагранжева механика, скрытые симметрии, конституционные законы).

LOKAN: только синтетические функции в `lokan_prod_group.ipynb`. Без хотя бы одного реального примера статья будет значительно слабее.

---

### 4.2 Важные отсутствия (P1)

**5. Система контрольных точек: `saveckpt`, `loadckpt`, `rewind`**

NexusKAN (предшественник) **уже имеет** `rewind()` и `saveckpt()` — они не были перенесены в LOKAN. Это один из 3 главных "трюков" символьной регрессии в MultKAN.

```python
# Есть в NexusKAN, нет в LOKAN:
model.rewind('0.1')   # откат к версии для тестирования гипотезы
```

**6. `prune_input()` — удаление нерелевантных входов**

MultKAN: `model.prune_input(threshold)` — удаляет входы с низкими attribution scores.

LOKAN: есть `prune_node`, `prune_edge`, `prune` — но нет специализированной обрезки входов.

**7. `expand_depth()`, `expand_width()`, `perturb()`**

Нужны для сценария "скомпилировать → расширить → дообучить". В LOKAN нет ни одного из этих методов.

**8. `auto_swap()` — анатомическая модульность**

Перестановка нейронов для минимизации длины связей. Делает кластеры визуально очевидными на графе сети.

**9. `module()` — явное задание модульных структур**

```python
model.module(0, '[0,1]->[0,1]')  # x₀, x₁ образуют отдельный модуль
```

В контексте LOKAN это особенно интересно: можно задать априорную структуру операционных групп через logits, а не только через connectivity.

**10. Тесты функциональной модульности**

`test_separability()`, `test_general_separability()`, `test_symmetry()` — Hessian-based детекция структуры.

---

### 4.3 Желательные дополнения (P2)

**11. `feature_interaction()`** — обнаружение взаимодействий между признаками.

**12. `history()` / `log_history()`** — журнал операций для воспроизводимости.

**13. `speed()` / оптимизации памяти** — MultKAN снизил потребление с O(LN²G) до O(LNG). LOKAN использует тензор логитов (in_dim × out_dim × G), что создаёт свой профиль памяти.

**14. `evaluate(dataset)`** — стандартизированный метод оценки.

## 5. Концептуальное сравнение: LOKAN vs MultKAN

Это самый важный раздел — позиционирование LOKAN в статье.

| Аспект | MultKAN | LOKAN |
|---|---|---|
| **Как задаётся тип операции** | Вручную пользователем при инициализации | **Автоматически обучается** из данных |
| **Когда известна структура** | До обучения | После обучения (через τ → 0) |
| **Гибкость** | Фиксированная топология узлов | Мягкая маршрутизация, возможна любая комбинация |
| **Количество параметров** | +0 (умножение без параметров) | +in_dim·out_dim·G логитов |
| **Интерпретируемость в процессе** | Сразу (явные узлы) | Только после анниллинга |
| **Применимость к неизвестным зависимостям** | Ограничена (нужно знать структуру) | **Высокая** (структура обнаруживается) |
| **Применимость к известным зависимостям** | Оптимальна (+ kanpiler) | Избыточна |

**Ключевой тезис для позиционирования LOKAN**:

MultKAN решает задачу *представления* мультипликативных структур (если вы их знаете). LOKAN решает задачу *обнаружения* мультипликативных структур (если вы их не знаете). Это не конкурирующие архитектуры — это дополняющие друг друга инструменты на разных этапах научного познания.

## 7. Уникальные преимущества LOKAN, которые нужно показать в статье

Эти возможности есть в LOKAN, но **отсутствуют в MultKAN** — их нужно демонстрировать явно:

### 7.1 Автоматическое обнаружение операционной структуры

**Эксперимент**: обучить и MultKAN, и LOKAN на `f = x₀·x₁ + x₂·x₃` с нуля (без указания структуры).

- MultKAN без `mult_arity > 0` в width: не сможет представить произведение в одном слое
- LOKAN: автоматически маршрутизирует x₀, x₁ в одну мультипликативную группу, x₂, x₃ в другую

Это core contribution LOKAN — **наглядный рисунок-1** для статьи.

### 7.2 Непрерывный переход sum ↔ product

MultKAN: операция — дискретный выбор (бинарный тип узла).

LOKAN: операция — непрерывный параметр (softmax probability). Это позволяет:
- Плавный gradient flow через операционный выбор
- Анализ "уверенности" маршрутизации (entropy H_ops → 0 при τ → 0)
- Robustness analysis: как часто LOKAN находит правильную структуру при разных seed

**Рисунок convergence**: кривая H_ops(epoch) — снижение энтропии операций в процессе обучения с температурным отжигом.

### 7.3 Обнаружение структур с нечёткими границами

В реальных данных граница sum/product часто нечёткая. MultKAN требует жёсткого выбора; LOKAN может оставить "смешанную" операцию с p ≈ 0.5, что само по себе является информативным сигналом.

## 9. Резюме

| | LOKAN | MultKAN |
|---|---|---|
| Главная идея | **Обучаемый выбор операции** | Явные узлы умножения (ручная настройка) |
| Глубина философии | Открытие структуры | Представление известной структуры |
| Зрелость API | Средняя (нет fit, нет kanpiler) | Высокая (полный пакет) |
| Теоретическая база | Нужна теорема (есть скелет) | Есть (через теорему КА) |
| Физические приложения | ❌ Нет | ✅ 4 класса задач |
| Benchmark vs LOKAN | N/A | Нужно сравнение |
| Читаемость кода | Хорошая (чистый модуль) | Избыточная (legacy методы) |

**Главный вывод**: LOKAN концептуально сильнее MultKAN в задаче *автоматического обнаружения* операционных структур. Но MultKAN значительно превосходит LOKAN по готовности к использованию и демонстрации реальных научных приложений. Статья о LOKAN должна сделать центральным именно автоматическое обнаружение — это то, чего MultKAN принципиально не умеет.
